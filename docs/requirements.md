# 要求仕様 — 式神鑑定

> 本書はプロダクトの「何を実現するか」を定義する。

## Phase 1 MVP 方針

Phase 1 は local-first MVP とする。

- 鑑定生成は端末内で完結
- 履歴とキャッシュはローカル保存
- オフラインでも主要機能を利用可能
- 外部バックエンド運用を持たない

## 主要要求

| ID | 要求 |
|---|---|
| FR-ON-01 | 5 ステップ以内で初回鑑定まで到達できる |
| FR-FT-01 | 晴明スタイルの鑑定文をローカル生成できる |
| FR-FT-02 | 鑑定履歴を端末内へ保存できる |
| FR-FT-03 | 同一入力ではキャッシュ済み鑑定を返せる |
| FR-EN-01 | 六壬神課エンジンを純粋関数で実装する |
| FR-EN-02 | Vision Framework による観相分析を提供できる |
| FR-PY-01 | StoreKit 2 による課金判定ができる |
| FR-OF-01 | オフラインでも鑑定を返せる |
| FR-PR-01 | 顔・手画像を端末外へ送信しない |

## 非機能要求

| ID | 要求 |
|---|---|
| NFR-PF-01 | 鑑定生成 p95 2 秒以内 |
| NFR-OF-01 | 機内モードでも鑑定可能 |
| NFR-CO-01 | 月額運用コストを極小化 |
| NFR-PR-01 | 個人データを外部送信しない |
| NFR-AC-01 | iOS 17 以降対応 |

## 将来拡張

将来的に以下を満たす場合のみクラウド導入を検討する。

- 複数端末同期
- AI 生成強化
- コミュニティ機能
- サーバ側分析
- 高度な課金検証
